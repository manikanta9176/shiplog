# shiplog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a browser-only end-of-day log that stores what shipped and copies a day as Markdown.

**Architecture:** Next.js App Router. Pure functions in `lib/entry.ts` validate, group, edit, delete, and render Markdown. `lib/storage.ts` reads and writes `localStorage`. Client components render the form and the day list. Nothing is fetched.

**Tech Stack:** Next.js App Router, React, TypeScript, Tailwind CSS, pnpm, Vitest.

## Global Constraints

- Entries live in `localStorage` under `shiplog.entries`.
- No API routes, database, accounts, or environment variables.
- `validateDraft` checks date, then shipped text, then link, and returns the first error.
- Edit keeps `id` and `createdAt`.
- `pnpm test` and `pnpm build` pass with no environment variables.
